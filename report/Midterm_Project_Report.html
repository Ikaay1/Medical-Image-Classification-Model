Project overview

My project looks at whether uncertainty estimation methods can help identify wrong predictions in medical image classification. A model may perform well on clear images but struggle when images have noise, blur, or lower contrast. I want to find out whether its confidence gives a useful warning when this happens.

So far, I have trained the classifier, tested it on altered images, and implemented all three uncertainty methods. The main finding is that accuracy drops much faster than confidence. The methods reduce this gap, but the model still makes many wrong predictions with high confidence.

Training the baseline model

I used PathMNIST, a public dataset with nine tissue classes from colorectal cancer slides. It contains 89,996 training images, 10,004 validation images, and 7,180 test images. I chose the 64 × 64 version because it gives me more image detail to work with when adding blur.

The test images come from a different hospital than the training and validation images. This lets me check how the model handles a change in the data even before I alter the images.

I built a convolutional neural network using Python 3.11, TensorFlow 2.18, and Keras 3. It has four convolution blocks and about 1.24 million parameters. Training took 40 epochs, or about 165 minutes. Epoch 34 had the lowest validation loss. I included dropout during training and kept the raw model scores so I could use them for the uncertainty methods later.

On validation images, average confidence was close to accuracy. On the test images, confidence was about 3.5 percentage points higher than accuracy. Of the 468 wrong test predictions, 96 had confidence above 99%. This shows why confidence alone may not be enough to judge whether a prediction is reliable.

The model struggled most with cancer-associated stroma. It correctly identified about 58% of these images and often confused them with debris or smooth muscle.

Testing altered images

I added Gaussian noise, Gaussian blur, and reduced contrast to the test images only. I used five severity levels for each change. I kept the training data unchanged and used fixed random seeds so each uncertainty method would receive the same altered images.

Choosing the severity levels took more work than I expected. My first noise settings were too strong and pushed several levels to around chance accuracy. I wrote a script to test a wider range of settings on 2,500 images, then chose levels that gave a gradual drop in performance. I aimed for a lowest accuracy of about 40% on this sample. Results on the full test set were sometimes lower.

Comparing uncertainty methods

I implemented softmax confidence, temperature scaling, and Monte Carlo Dropout. Softmax uses the model’s usual confidence score. Temperature scaling adjusts the raw scores to change confidence without changing the predicted class. Monte Carlo Dropout runs the model several times with dropout active and averages the results.

For temperature scaling, I fitted a temperature of 1.2759 using half of the validation set and checked it on the other half. I did not use the test set to fit it. For Monte Carlo Dropout, I used 30 passes per image. I also measured mutual information, which captures how much those passes disagree.

Both temperature scaling and Monte Carlo Dropout reduced the average gap between confidence and accuracy compared with softmax. The table shows this gap at severity 5, in percentage points. A smaller gap means average confidence is closer to accuracy, but it does not by itself prove that a method can identify individual errors.

Monte Carlo Dropout gave the smallest gap under noise at every severity. Under blur and reduced contrast, the better method depended on severity. None of the methods fully solved the overconfidence problem.

Temperature scaling left the predicted classes unchanged. Monte Carlo Dropout changed some predictions and raised accuracy under the strongest noise from 32.4% to 37.0%. However, it also lowered accuracy in some blur and contrast settings.

Mutual information increased with severity for all three image changes. This makes it worth testing as a possible warning signal, though I still need to measure how well it identifies wrong predictions.

I also checked whether temperature scaling changed the order of confidence scores. In these preliminary checks, the scores stayed almost in the same order, and error-detection AUROC changed by less than 0.005. The full comparison is still part of Milestone 4. Adjusting confidence and detecting errors are different tasks.

As an extra check, I fitted temperatures directly on individual test conditions. This uses labels that would not normally be available, so it is only a reference. Even this approach left a confidence gap under strong noise, suggesting that one temperature may not be enough for badly altered images.

Challenges and solutions

Environment setup was an early challenge. TensorFlow did not work with the Python versions I first tried, and the GPU plugin was incompatible with the newer TensorFlow version. I switched to Python 3.11 and TensorFlow 2.18 with tensorflow-metal 1.2.0. I checked CPU and GPU outputs before continuing. Predicted classes matched, and numerical differences were very small.

During training, validation accuracy stayed near chance even though training accuracy was improving. After checking the data and model behavior, I traced this to Batch Normalization’s stored statistics. Reducing its momentum from 0.99 to 0.9 fixed the issue. In a two-epoch check, validation accuracy rose from 10.9% to 64.0%.

The severity settings also needed adjustment. Some were too strong, and one selection attempt chose unchanged images as the first contrast level. I updated the calibration script to choose progressively stronger changes without reusing the clean setting.

For Monte Carlo Dropout, calling the model in training mode would also change how Batch Normalization works. I replaced only the dropout layers so dropout could stay active while Batch Normalization remained in inference mode. A check with dropout set to zero reproduced the original model’s output exactly.

Repeated Monte Carlo Dropout runs still varied on the GPU, even with a fixed seed. Across five seeds, accuracy ranged from 94.15% to 94.50%. I will account for this variation when interpreting small differences between methods.

Progress compared with the proposal

I have completed the first three milestones and am on schedule. I followed the proposed approach of training a medical image classifier, altering only test images, and comparing the three uncertainty methods. The formal error-detection and calibration measurements are still incomplete.

I trained a smaller model from scratch, which the proposal allowed. I also added severity calibration and the extra temperature checks because they helped me interpret the results. I left contrast and brightness changes out of training augmentation so they would not overlap with the changes being studied.

Next steps

Next, I will calculate error-detection AUROC to measure how well each method ranks wrong predictions above correct ones. I will also calculate expected calibration error and create reliability diagrams to check how closely confidence matches accuracy.

I will test whether removing the least confident predictions improves accuracy and compare mutual information with the usual confidence score. Then I will bring the results together and write the final analysis, including the cost of running Monte Carlo Dropout 30 times per image.

The study uses one model and one dataset, and the image changes are artificial. The selected severity levels also depend on this model. I will keep these limits clear when explaining what the results show.
